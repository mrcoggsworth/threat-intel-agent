# Hermes Agent Project Context & Guidelines

## Overview

CTI-Hermes is a phased, independently deployable public-CTI service. Phases 2 through 4 implement bounded public-source ingestion, RSS/Atom and CISA KEV normalization, evidence metadata, deterministic extraction, PostgreSQL persistence, deduplication, and independent scheduling. Phase 5 adds bounded public enrichment and explainable priority scoring. Phase 6 adds deterministic historical correlation, contradiction visibility, guarded model proposals, and evidence-linked resurfacing. Phase 7 adds evidence-backed report validation, detection artifacts, separate hunting/remediation guidance, safe renderers, and rollback-safe publication persistence. Phase 8 adds the dynamic portal, public projections, and private token-gated operations; production deployment remains planned.

## Tech Stack

- **Python**: 3.12+
- **Package Manager**: `uv` with a committed `uv.lock`
- **Architecture**: `src/hermes_cti/` with explicit API, core, model, database,
  ingestion, extraction, enrichment, correlation, detection, reporting,
  portal, and CLI boundaries.

## Guidelines

- Follow PEP 8 standards and strict type hinting.
- Keep module interfaces typed and decoupled.
- Keep deterministic extraction, enrichment inputs, scoring, and persistence provenance-preserving; keep model-assisted content generation, portal publication surfaces, and deployment operations behind explicit review and later phases.
