# Sigma rule generation and validation

Generate a Sigma rule only from concrete observable behavior and cite the
evidence. Include stable UUID, status, references, ATT&CK tags, logsource,
detection, false positives, and level. Translate the same logic to Splunk SPL
and KQL without inventing fields. Validate YAML/schema and report unavailable
native converters instead of claiming validation.
