## Impact

- Web application is serving locally and public liveness on 9443 returns 200.
- Private readiness on 9444 returns 200 when requested at `/health/ready`.
- No successful ingestion run is recorded. The latest four runs (2026-08-26 00:39Z, 02:00Z, 17:32Z, and 2026-08-27 00:00Z) are `failed`.
- Latest run `b628f6c8-c83f-5d11-b9ef-99b45bd1d075` completed with 2 failed sources out of 14: Google TAG HTTP 404 and Microsoft Security Response Center malformed XML. Other 12 sources completed with HTTP 200.
- Public CTI data remains present (1,846 source documents, 1,875 evidence claims, 3,425 indicators, 18 reports, 19 publications), but ingestion freshness is degraded.

## Likely causes

1. **High confidence:** production is running mixed mutable local images; web was recreated separately from scheduler/monitor. This explains monitor failures and makes behavior non-coherent.
2. **High confidence:** source freshness failure is real but bounded to two source adapters: Google TAG endpoint returns 404 and MSRC payload is not parseable as configured. Earlier runs also show network failure during the 02:00Z restart window.
3. **Medium confidence:** the 2026-08-26 PostgreSQL/container restart caused a short outage and backup retries, but PostgreSQL recovered and is healthy now.
4. **Not a confirmed integrity failure:** the 223 unmatched `entity_evidence` rows are NULL optional source-document links, not broken non-NULL references; the FK is validated.
